# スキマ — Google カレンダーと同期する日程調整

候補日時を出して、○×を集めて、決まったら **Google カレンダーに登録して Google Meet の
リンクまで作る**。その内容を **LINE・Messenger・メールにワンタップで送る**ところまでを
ひと続きにしたアプリです。

調整さんの「みんなで○×をつけて決める」使い方に、Google カレンダー連携を足したもの、
と考えてください。

---

## なぜ作ったか

Google カレンダーの「予約スケジュール」は、**相手が自分の空き枠を1つ選ぶ**予約受付ページです。
**複数人の都合を突き合わせて多数決で決める**という調整さん的な用途はカバーしていません。
一方、調整さんにはカレンダー連携も会議URLの発行もありません。

その**あいだが抜けている**ので作りました。既存サービスとの比較と、
LINE / Messenger へ自動送信するときの制約は [`docs/research.md`](docs/research.md) に
出典つきでまとめています。**先にそちらを読むことをおすすめします。**

---

## できること

| 段階 | できること |
|---|---|
| **候補を作る** | Google カレンダーの**予定が入っていない時間**から候補を自動で並べる。手で足すこともできる |
| **集める** | 参加者は**ログイン不要**。リンクを開いて名前と○△×を入れるだけ |
| **決める** | ○=2点 / △=1点 で集計して並べ替え。決めるのは主催者 |
| **登録する** | 確定すると Google カレンダーに予定を作成。**Google Meet のリンクを自動発行** |
| **伝える** | 確定文面をワンタップで LINE・Messenger・メールへ。Slack / Discord の Webhook にも送れる |

オンライン / 対面 / 両方を選べます。オンラインなら Meet の自動発行か、
Zoom などの URL を自分で指定するかを選べます。

## 動かす

### 必要なもの

- **Node.js 22.5 以上**（データベースに Node 標準の `node:sqlite` を使っています）

### 手順

```bash
npm install
cp .env.example .env.local
npm run dev
```

http://localhost:3000 を開きます。
**Google の設定をしなくても、日程調整そのものは動きます。**

### Google 連携を有効にする

空き時間からの候補作成と Meet リンクの自動発行には設定が要ります。
アプリ内の `/setup` に手順を出していますが、要点だけ書くと：

1. Google Cloud Console でプロジェクトを作り、**Google Calendar API** を有効化
2. OAuth 同意画面でスコープに `calendar.events` と `calendar.freebusy` を追加
3. OAuth クライアントID（ウェブアプリケーション）を発行し、
   承認済みリダイレクトURIに `http://localhost:3000/api/auth/google/callback` を登録
4. `.env.local` に `GOOGLE_CLIENT_ID` と `GOOGLE_CLIENT_SECRET` を書いて再起動

> **注意**：同意画面を「外部」にしてテスト中の状態では、
> **テストユーザーに登録したアカウントしかログインできません**。
> 一般公開するには Google の審査が必要です。

---

## 要求する権限について

Google に求めているのは**2つだけ**です。

- `calendar.events` — 確定した予定を**作る**ため
- `calendar.freebusy` — **空き / 予定あり**の時間帯だけを読むため

`calendar.readonly`（予定のタイトルや参加者まで読める権限）は**要求していません**。
日程調整に必要ないからです。freeBusy が返すのは「この時間は埋まっている」という
区間だけで、**予定の中身は取得しません**。

## LINE / Messenger への「自動送信」について

「決まった瞬間に、やり取りしているトークへ自動で流したい」——
これは技術的に完全な形では実現できません。理由を正直に書きます。

- **LINE Notify は 2025年3月31日に終了**しました。後継は Messaging API です。
- Messaging API で送るには **LINE 公式アカウント**が要り、
  送信先が**その公式アカウントを友だち登録している**必要があります。無料通数の上限もあります。
- **個人どうしの普通のトークルームに、外部アプリが割り込むことはできません。**
- Messenger には **24時間ルール**があり、Facebook ページとアプリ審査が前提です。

そこで**2通り**を用意しています。

### 既定：ワンタップ共有（設定不要）

確定した瞬間に、そのまま貼れる文面ができます。
スマホでは **OSの共有シート**から LINE・Messenger・メールなど、
**入っているアプリへ直接渡せます**。ボタンを1回押す手間だけが残ります。

### 任意：登録した宛先へ自動送信

LINE 公式アカウントの宛先ID、または Slack / Discord の Webhook URL を登録しておくと、
ボタン一つで同じ文面を流せます。`LINE_CHANNEL_ACCESS_TOKEN` の設定が必要です。

> **正直な見立て**：1タップの手間を消すために公式アカウントを開設するのは、
> 個人利用では割に合わないかもしれません。この機能が効くのは、
> **Slack や Discord を使っているチーム利用**のほうだと考えています。

## 本番で使うときの注意

**SQLite はファイルなので、Vercel のようなサーバーレス環境では保存が消えます。**
継続運用するなら Postgres などへの差し替えが必要です。
SQL は `src/lib/db.ts` と `src/lib/repo.ts` の中だけに閉じ込めてあるので、
差し替えの影響範囲はそこに収まります。

また、以下は**実装していません**。社外に広く公開するなら追加が要ります。

- レート制限 / スパム対策
- 監査ログ
- 保存データの暗号化
- 招待制・アクセス制御（**調整ページはURLを知っていれば誰でも見られます**）

## 開発

```bash
npm run dev     # 開発サーバー
npm run build   # 本番ビルド
npm run lint    # 型チェック（tsc --noEmit）
```

### 通し確認（作成 → 回答 → 確定 → 共有）

実際のブラウザで一連の流れを通すスクリプトを用意しています。
Playwright は本体の依存に含めていないので、必要なときだけ入れてください。

```bash
npm i -D playwright && npx playwright install chromium
npm run build && npm start    # 別のターミナルで起動しておく
npm run test:e2e
```

Google 連携が要らない範囲（候補作成・回答・集計・確定・共有文面・権限チェック）を
対象にしています。**カレンダー登録と Meet の発行は、実際の Google 認証情報での手動確認**が必要です。

設計の詳細は [`docs/architecture.md`](docs/architecture.md) にあります。
